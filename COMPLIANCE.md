Prepared for the initial publication, 2026-11-20.

## Original name

`foriscope` was coined for this project (Latin *foris*, "outside", +
*-scope*). Collision-checked against GitHub, PyPI, and web products; the
record, including rejected candidates and near names, is in
[NAME_CHECK.md](NAME_CHECK.md). No existing product, package, or repository
carries the name.

## Original code and copy

All code and documentation in this repository were written for this project.
The design discipline (probe-backed claims, reason-coded refusals, coverage
ledger, clean-room audit log) follows the verified-or-refuse pattern of the
author's earlier tools (pairseal, evalcrucible, hypothescope), reimplemented
here from scratch for a new target class (HTTP APIs). No code, text, names,
or structure were copied from any third-party explainer, reverse-engineering
tool, or landscape subject. The landscape analysis that motivated the
position (an internal planning document) was used for its *idea* only.

## Secrets scan

The tree was scanned before publication for credential-shaped strings
(API keys, tokens, passwords, private-key blocks, and the author's
employer-identifying references). The only key material present is the
example runs' audit signing keys under `examples/*.key`: these are

they protect nothing and grant access to nothing.

## Clean-room method statement

foriscope's operating method is clean-room by construction, and every run
proves it about itself:

1. The target is examined **only** through the HTTP requests recorded in
   the run's audit log — ordinary requests any client could make.
2. No source code, binaries, or internal documentation of the target are
   read; no authentication is bypassed and no access control is
   circumvented (unauthenticated probing observes refusals of access as
   facts, and reports behavior behind authentication as refused claims).
3. The operator's authorization attestation is recorded in the log before
   probing; the CLI will not run without it.
4. The audit log is hash-chained and HMAC-signed, so the record of what
   was accessed — and, by omission, what was *not* — is tamper-evident.

This statement describes the tool's method; it is not legal advice, and
authorization to examine any given system remains the operator's
responsibility.
